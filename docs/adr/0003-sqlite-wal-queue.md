# ADR-0003: SQLite WAL як БД і черга + Litestream

**Статус:** Accepted

## Контекст
Потрібні метадані (проєкти, асети, пресети), надійна черга задач і outbox вебхуків. Окремі Postgres і Redis/Valkey — це +200–400 МБ RAM і ще два сервіси для бекапу й оновлень.

## Рішення
- `modernc.org/sqlite` (чистий Go, без CGO), WAL, `synchronous=NORMAL`, одне зʼєднання для запису + пул читачів.
- Черга — таблиця `jobs` з атомарним захопленням (`UPDATE … RETURNING`) і `lease_until`.
- Litestream безперервно реплікує WAL у `kadr-system` (R2).
- Доступ до даних тільки через `Store`-інтерфейс; запити генерує sqlc.

## Наслідки
- ~5–10 МБ RAM; бекап і відновлення одного файлу; RPO ≈ 1 с.
- Пропускна здатність запису — сотні–тисячі транзакцій/с, з великим запасом для S1.
- Один екземпляр control plane. Горизонтальне масштабування воркерів — через internal lease API (S2); кількох control plane — через Postgres-драйвер `Store` (S3).

## Альтернативи
- Postgres + Valkey/BullMQ — надлишково для одного вузла.
- bbolt/BadgerDB — немає SQL, складніша аналітика для адмінки.
