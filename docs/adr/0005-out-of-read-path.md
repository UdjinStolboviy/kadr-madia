# ADR-0005: Kadr поза шляхом читання

**Статус:** Accepted

## Контекст
Проксування переглядів через Proxmox знищує переваги R2 (нульовий egress, глобальний CDN), створює єдину точку відмови й порушує ToS тунелю для відео.

## Рішення
- **Публічні:** `kadr-public` з Custom Domain `cdn.<domain>`, Cache Everything, `immutable`. Формат обирає браузер через `<picture>` (AVIF → WebP), тож Worker на публічному шляху не потрібен.
- **Приватні:** Worker `kadr-edge` на `media.<domain>` з read-binding до `kadr-private`. Перевіряє HMAC (`kid`, `exp`), кешує через Cache API з ключем без підпису, підтримує Range-запити для відео.
- Підписи генерує SDK у бекенді проєкту локально.

## Наслідки
- Збій Kadr не впливає на перегляди; доступність видачі дорівнює SLA Cloudflare.
- Безкоштовний план Workers: 100 тис. запитів/день лише для приватних файлів; при перевищенні — Workers Paid ($5/міс) або presigned GET як fallback.
- Відкликати конкретне приватне посилання до `exp` не можна (компроміс stateless-підпису). Тому TTL короткий (≤ 1 год), а в разі інциденту виконується ротація `kid`.

## Альтернативи
- Presigned GET напряму з R2 S3 endpoint — не кешується в CDN, довгі URL; лишається fallback.
- Worker на публічному шляху для `f_auto` — зайві виклики й витрати.
